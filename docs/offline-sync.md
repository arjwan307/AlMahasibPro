# الأوف لاين والمزامنة عند فتح التطبيق
الحالة: نُفذ الأساس العام للويب في `public/offline-sync.js` وعقد الخادم في `/api/v1/sync`.
اعتماد التجارة مدمج الآن كعملية `commerce.commit` idempotent. قواعد تخصيص المخزون
للجهاز منفذة للكاشير: التنزيل الأولي، الحجز المحلي، منع التجاوز، واستعادة الحجز عند
رفض العملية. إغلاق الشفت محليًا `submitted_pending_sync` ولا يعد مغلقًا خادميًا حتى
وصول العملية. نطاق المندوب منفذ بتنزيل العملاء والمسار ومخزون السيارة والدين والعهدة،
وبفحص محلي يعاد التحقق منه داخل معاملة الخادم.
## أول استخدام
اتصال إلزامي للمصادقة وتسجيل الجهاز وتنزيل نطاق الشركة والصلاحيات والمواد والأسعار والعملاء والمخصص من المخزون.
تخزين محلي منفصل لكل شركة وحساب؛ تغيير الحساب لا يُرسل طابور الحساب السابق.

## عند كل فتح أو استئناف أو عودة اتصال
1. قفل مزامنة واحد للجهاز؛ التحقق من الحساب والجهاز والصلاحيات.
2. إرسال العمليات غير المؤكدة بالترتيب مع تبعياتها.
3. تأكيد كل عملية منفردة بعد commit فقط؛ الاحتفاظ بالأصل المحلي.
4. تنزيل التغييرات تدريجيًا بمؤشر cursor مستقل لكل نطاق.
5. تحديث وقت النجاح الكامل وعرض المعلق والمرفوض والتعارضات.
لا تعلّق الواجهة انتظارًا بلا نهاية؛ اعرض البيانات المحلية وقدم حالة المزامنة.

## عقد العملية
operation_id UUID يولد مرة واحدة؛ device_id وcompany_id وuser_id،
client_sequence وschema_version وentity_version وdependencies،
occurred_at محلي وreceived_at خادم وpayload_hash وpayload.
الخادم يفرض UNIQUE(company_id, operation_id) ويعيد نفس نتيجة الاعتماد عند تكرارها.
نفس المعرف بمحتوى مختلف يُرفض، ولا يُستبدل بصمت.
حالات النقل: pending، sending، acknowledged، retry، rejected، conflict.
عند الانهيار تعود sending لإعادة المحاولة؛ لا تُحذف عملية لم يصل تأكيدها.
backoff مع jitter؛ إعادة محاولة أخطاء الشبكة والمؤقتة، لا أخطاء قواعد العمل نهائيًا.

## المخزون والصندوق
تخصيص كمية لكل جهاز يقلل التنافس، ومخزن سيارة المندوب هو حد مخزونه المستقل.
لا يمكن تخصيص الكمية نفسها لجهازين؛ المرتجع الأوف لاين مرتبط بفاتورة محلية معروفة.
إيقاف بيع المخصص عند نفاده؛ تجاوز الكمية يحتاج اتصالًا واعتمادًا.
مخزون السيارة مخزن مستقل. حدود الائتمان والخصومات والعمل دون اتصال لها سياسة ومدة صلاحية.
لا تعتمد أرصدة كلية محلية قديمة على أنها محدثة.

## القيود
تُمنع أو تؤجل عمليات تتطلب موافقة مركزية: صلاحيات، صرف رواتب، تجاوز مخزون/ائتمان، إقفال مالي.
إغلاق شفت وتسليم عهدة محليًا = submitted_pending_sync، ثم اعتماد خادم.
الأصل المالي append-only، والتصحيح عملية جديدة مرتبطة به.
عدم استخدام last-write-wins للمال أو المخزون.
تعارض تحرير مسودة يستخدم entity_version مع شاشة مراجعة.
تغييرات وحذف البيانات المرجعية تنزل tombstones؛ لا حذف للمستندات المعتمدة.
