# استيراد البيانات الآمن

تفتح شاشة `/data-import.html` من شريط واجهة الشركة. تدعم العملاء والموردين والمواد،
من CSV بترميز UTF-8 وExcel XLSX وجدول SQLite عادي، ومن PostgreSQL وMySQL مهيأين مسبقًا.
لا تدعم XLS القديم أو صيغ Excel أو وحدات VBA أو ملفات النسخ الاحتياطي `domain_state`.
الحد: 3 ميغابايت للملف، 5000 سجل، 30 عمودًا؛ XLSX حتى 32 ميغابايت بعد فك الضغط.
القراءة في عامل مستقل بحد ذاكرة ومهلة، والملف الأصلي لا يحتفظ به في قاعدة التطبيق.

## الخطوات

1. سجل الدخول بحساب إدارة الشركة مع صلاحية إدارة نوع البيانات وصلاحية `accounting.post` للأرصدة غير الصفرية.
2. اختر الفرع والتاريخ والمصدر وطابق أسماء الأعمدة. الأعمدة الافتراضية:
   - العملاء والموردون: `code,name,phone,openingBalance,currency`.
   - المواد: `sku,name,unitCode,description`. الوحدة موجودة مسبقًا في الشركة.
3. أدخل الصافي ومجموع الأرصدة الموجبة والقيمة المطلقة للأرصدة السالبة، لكل عملة في المصدر، من تقرير مستقل.
4. راجع جميع التعارضات والمجاميع والمعاينة ثم اعتمد. تعرض الشاشة أول 100 سجل؛ يفحص الخادم جميع السجلات.

مبلغ العميل الموجب دين عليه، والمورد الموجب دين له. السالب يعكس الاتجاه.
المطابقة مستقلة لكل عملة (IQD/USD)، وتستخدم أرقامًا صحيحة مقاسة إلى ست منازل؛
لا جمع بين العملات ولا تخمين للفواصل. استخدم نقطة عشرية ودون فواصل آلاف.
يجمع التقرير `debit` المبالغ الموجبة و`credit` القيمة المطلقة للسالبة في المصدر؛
للموردين هذا وصف اتجاه المصدر، ويعكس القيد الدائن/المدين حسب طبيعة المورد.

## العزل والاعتماد

هوية الشركة مشتقة من الجلسة. تُرفض أعمدة هوية الشركة/المستأجر/الفرع والمعرفات؛
لا تُنسخ المستخدمون أو الجلسات أو الصلاحيات. ينشئ التطبيق معرفات جديدة.
البيانات الرئيسية مشتركة على مستوى الشركة في النموذج الحالي، لذلك يُمنع هذا المسار
عن حساب مقيد بفرع أو مخزن أو مندوب. الفرع المختار يحدد أبعاد القيود الافتتاحية،
ولا يجعل العميل أو المورد أو المادة سجلًا خاصًا بالفرع.

رمز مكرر أو هاتف مكرر أو وحدة غير معروفة أو اختلاف المجاميع يمنع الدفعة كاملة.
لا تحديث أو استبدال للسجلات القائمة، ولا كشف لسجلات شركة أخرى.
المعاينة محفوظة 30 دقيقة ومربوطة بالشركة والمستخدم وبصمة المحتوى؛ حتى 20 معاينة معلقة.
إعادة الاعتماد لنفس الدفعة تعيد النتيجة نفسها. إعادة رفع نفس الملف تُرفض لتكرار الرموز.
الاعتماد يعيد فحص الصلاحيات والفرع والوحدات والتكرار والفترة المالية.
كل السجلات والقيود والأرصدة وحركة دين العميل والتدقيق تُحفظ في معاملة SQLite واحدة.
الفشل يتراجع عن الدفعة بالكامل. الأرصدة تُسجل مقابل `3000-EQUITY`؛
العملاء `1100-AR` والموردون `2100-AP`، مع ربط القيد بالطرف والدفعة والفرع.
يُمنع حذف طرف له رصيد مرحل، أو عكس قيد استيراد منفردًا لفصل الحساب العام عن رصيد الطرف.
لم تُضف دورة إلغاء دفعة مستوردة بعد؛ راجع المعاينة قبل الاعتماد.

وجهة الحفظ المدعومة حاليًا هي SQLiteStore المحلية؛ لا يفعل هذا التغيير الاستيراد
إلى مخزن PostgreSQL أو MongoDB المستهدف ولا يشغّل ترحيل إنتاج.
موصلات المصدر مستقلة عن محرك اعتماد الدفعات ولا تحصل على مخزن التطبيق.

## مصادر PostgreSQL وMySQL

تُضبط `DATA_IMPORT_SOURCES_JSON` على الخادم فقط، ولا تُرسل بيانات الاتصال للمتصفح.
لكل اسم مصدر: `format` (`postgres` أو `mysql`)، `targetCompanyId`, `targetBranchId`,
`table`, `columns`, `companyColumn`, `companyValue`, `branchColumn`, `branchValue`, `connection`.
مثال بنيوي (قيم توضيحية):

```json
{
  "legacy-customers": {
    "format": "postgres",
    "targetCompanyId": "TARGET-COMPANY-UUID",
    "targetBranchId": "TARGET-BRANCH-UUID",
    "table": "legacy_customers",
    "columns": ["code", "name", "phone", "openingBalance", "currency"],
    "companyColumn": "company_id",
    "companyValue": "SOURCE-COMPANY",
    "branchColumn": "branch_id",
    "branchValue": "SOURCE-BRANCH",
    "connection": {
      "host": "DATABASE-HOST",
      "port": 5432,
      "database": "DATABASE-NAME",
      "user": "READ-ONLY-USER",
      "password": "SECRET-FROM-SERVER-CONFIG"
    }
  }
}
```

في MySQL استخدم `format:mysql` والمنفذ 3306. الحساب له SELECT على الجدول المحدد فقط؛
فعّل TLS الموثوق حسب إعدادات المزود. لا تستخدم مستخدم الإنتاج للكتابة.
لا يقبل الطلب مضيفًا أو كلمة مرور أو SQL. الاستعلام SELECT محدد، بمرشحي شركة وفرع
ملزمين، ومعاملة قراءة فقط وحد سجلات ومهلة. المعرفات لاتينية بسيطة؛ لا جداول افتراضية
ولا أسماء مؤهلة أو استعلامات حرة. إذا احتجت تحويلًا في المصدر، جهز جدول تصدير منفصلًا.
تأكد من تطابق رموز العملات وإشارات الأرصدة قبل تجهيز المصدر.

## API والتحقق

`POST /api/v1/data-import/preview`: `entity,branchId,openingDate,mapping,expectedBalances,source`.
للملفات: `source:{format,content}` حيث content base64، ومع SQLite `table`، ومع Excel `sheet` اختياري.
لقواعد البيانات: `source:{format,name}` فقط. يعيد `preview` مع السجلات والمجاميع والتعارضات والبصمة.
`POST /api/v1/data-import/:batchId/commit`: `{previewHash}`، يعيد نتيجة الاعتماد أو 409 للتعارض.

اختبارات الملفات والاعتماد: `node --test tests/integration/data-import.test.js` على Node 24.
لا توجد اتصالات تلقائية بالمصادر الخارجية ولا بيانات اعتماد مضمنة في الاختبارات.
يلزم اختبار الموصلين على PostgreSQL/MySQL مستقلين قبل استخدامهما مع بيانات فعلية.
اختبار الموصلين الاختياري: `tests/integration/data-import-databases.test.js`.
يتطلب `TEST_DATA_IMPORT_SOURCES_JSON` بكائن يحوي مفتاحي `postgres` و`mysql`، بكل منهما
إعدادات المصدر أعلاه إضافة إلى `expectedRows` كمصفوفة السجلات النصية المتوقعة.
جهز في قاعدة الاختبار سجلات لعدة شركات وفروع؛ النتيجة المتوقعة تخص الشركة والفرع المهيأين فقط.
