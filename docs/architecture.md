# البنية
تطبيق خادم واحد منظم إلى وحدات في البداية، بدل تقسيمه مبكرًا إلى خدمات كثيرة.
نواة بيع واحدة وثلاث واجهات حسب النشاط. كل شركة قد تفعّل أكثر من نشاط.
الويب: إدارة وكاشير؛ أندرويد: كاشير ومندوب مع SQLite/Room؛ الويب المحلي: IndexedDB.

## عزل الموارد
خدمة Render مستقلة؛ PostgreSQL في instance/cluster مستقل؛ مخزن ملفات مستقل؛
أسرار ومستخدم قاعدة ونسخ احتياطي مستقلون. المشروع أو الحساب المشترك لا يعني موارد تشغيل مشتركة.
لا استخدام لعنقود MongoDB أو أقراص أو مفاتيح شنو منو والمراقب.
إمكانية تكامل حضور اختيارية لاحقًا عبر API، لا عبر مشاركة قواعد البيانات.

## حدود البيانات
company_id إلزامي في سجلات العمل، branch_id عند الحاجة.
الخادم يحدد الشركة من الجلسة، ولا يثق بشركة يرسلها العميل.
قيد فريد مركب ومعرّفات خارجية مركبة لمنع ربط سجل بشركة أخرى.
PostgreSQL RLS دفاع إضافي مع ضبط سياق المعاملة واختبار عزل الاتصال.

## الاعتماد
اعتماد مستند البيع ينشئ الفاتورة وحركة المخزون والدفعات والقيد بمعاملة واحدة.
الأموال NUMERIC مع العملة والدقة؛ ممنوع حسابها باستخدام float.
بعد الاعتماد يكون التصحيح بمستند عكسي/مرتجع، لا تعديل الأصل.
سجل outbox على الخادم للأحداث بعد نجاح المعاملة.
