# تقدم التنفيذ

## منجز — المرحلة الأساسية والتجارية والكاشير والمندوبون

- migration PostgreSQL إصدارية للشركات والفروع والمستخدمين والأدوار والصلاحيات والجلسات.
- تسجيل الشركة بحالة pending، واعتماد idempotent من مدير منصة منفصل، ثم تفعيل مالكها.
- كلمات مرور scrypt بملح مستقل، جلسات opaque لا تخزن التوكن الخام، cookie HttpOnly/SameSite.
- أدوار افتراضية لنطاق المشروع وصلاحيات API ونطاقات شركة/فرع/مخزن/جهاز/عملاء.
- اشتقاق الشركة من الجلسة، مفاتيح مركبة، وسياسات RLS مفعلة ومفروضة على جداول المستأجر.
- سجل تدقيق وسجلات مالية append-only، وقيود تمنع تعديل/حذف القيد المرحّل وتفرض عكسه.
- push/pull/status للمزامنة؛ UUID وبصمة محتوى وتسلسل جهاز، وإعادة نفس نتيجة العملية المكررة.
- عميل IndexedDB يحتفظ بالـoutbox بعد التأكيد ويزامن عند الفتح والاستئناف وعودة الاتصال.
- ربط نموذج الدخول الحالي بالـAPI وحماية الصفحات الحالية دون تغيير CSS أو التخطيط.
- اختبارات ذاكرة وPostgreSQL لمسارات الاعتماد والدخول والصلاحيات والعزل ومنع التكرار والحذف.
- مواد ووحدات أساسية وتحويل وحدات حتى 6 منازل عشرية، وأسعار بيع وشراء مؤرخة.
- عملاء بحد ائتمان، موردون، ومخازن قياسية/سيارة/نقطة بيع، وأرصدة كمية ومتوسط تكلفة.
- اعتماد شراء وبيع ومرتجع شراء ومرتجع بيع، مع ربط كل مرتجع بالمستند والبند الأصليين
  ومنع تجاوز الكمية الأصلية.
- دفعات نقد/بنك/بطاقة جزئية أو كاملة، والرصيد المتبقي في الذمم.
- معاملة ذرية واحدة تنشئ المستند والبنود والدفعات وحركة المخزون وتحدث الرصيد ومتوسط
  التكلفة وترحّل قيدًا متوازنًا وتكتب audit وserver outbox وsync change ونتيجة العملية.
- `commerce.commit` موحد للاتصال المباشر وطابور الأوف لاين؛ إعادة `operation_id` تعيد
  النتيجة ذاتها، وتغيير المحتوى بنفس المعرف مرفوض.
- ربط حفظ المادة والرصيد الافتتاحي في `warehouse.html`، وحفظ العميل والبيع في
  `sales.html`، مع بقاء CSS والتخطيط المرئي كما هما.
- أجهزة كاشير مستقلة بثلاثة أوضاع: مطعم/كافيه، ماركت، وشركات/مؤسسات، مع مخزن وسياسة
  خصم ومخصص أوف لاين منفصل لكل جهاز.
- فتح الشفت بمعرف يولده الجهاز وعهدة افتتاحية، ومنع أكثر من شفت مفتوح للجهاز.
- بيع الباركود والدفع النقدي والآجل والمختلط؛ الآجل والمختلط يتطلبان عميلًا، والنقد فقط
  يدخل في تسوية الصندوق.
- خصم على مستوى الفاتورة مع حد للجهاز؛ تجاوز الحد يتطلب `sales.discount.override` ويعاد
  فحصه على الخادم بعد المزامنة.
- وصل immutable برقم فريد وبيانات الطباعة، وواجهة طباعة عبر المتصفح.
- مرتجع كاشير مرتبط بالفاتورة والبنود الأصلية يعكس المخزون والنقد/الذمة والقيد.
- إغلاق الشفت يحسب النقد المتوقع من العهدة + المبيعات النقدية - المرتجعات النقدية،
  ويسجل المعدود والفارق. الإغلاق الأوف لاين يبقى محليًا `submitted_pending_sync` حتى
  وصول `pos.shift.close` واعتماده.
- IndexedDB يحجز مخصص الجهاز محليًا، يمنع تجاوزه، يعيد الحجز عند رفض العملية، ويزامن
  عند الفتح وعودة الاتصال. UUID يمنع تكرار الفاتورة والوصل والدفعات.
- يعاد فتح قاعدة الحساب من bootstrap محلي غير سري عند بدء التطبيق أثناء الانقطاع؛ أول
  استخدام وتغيير الحساب يظلان بحاجة لاتصال.
- صفحة كاشير مشتركة تحافظ على لغة التصميم الحالي وتغير سياقها حسب النشاط: طاولة/سفري
  للمطعم، مسار وباركود للماركت، ومرجع طلب/مشروع وعميل للمنشآت.
- migration `004_representatives.sql` لجداول المندوبين وإسناد العملاء والمسارات ومحطات
  الزيارة وتحويلات المخزون والطلبات وحركات دين العميل والتحصيل وعهدة النقد والتسليم
  والتعارضات؛ جميعها بعزل RLS مفروض ومفاتيح شركة مركبة.
- أدوار منفصلة للتشغيل والتحصيل والتسليم والمراجعة والإدارة. المندوب لا يعمل إلا على
  ملفه وعملائه المسندين ومخزن سيارته، والمشرف يراجع التسليم ولا يملك تنفيذ عمليات مندوب
  آخر بصفته مندوبًا.
- مخزن سيارة مستقل وتحميل موثق بتحويل مخزون ثنائي الطرف يحافظ على متوسط التكلفة ولا
  ينشئ إيرادًا أو مصروفًا، مع منع التحويل عند نقص المخزون.
- طلبات مندوب غير مالية، وتحويل اختياري للطلب إلى بيع. البيع والمرتجع يستخدمان محرك
  التجارة نفسه ويعتمدان المخزون والوثيقة والقيد وحركة الدين وعهدة النقد في معاملة ذرية.
- حد ائتمان للعميل قابل للتخصيص عند إسناده للمندوب، وفحص نهائي للخادم مع قفل العميل،
  إضافة إلى فحص مخزون السيارة وحد النقد المتاح للمرتجع.
- التحصيل يخفض `1100-AR` ويزيد `1150-REP-CASH-CUSTODY` ويسجل إيصالًا وحركة دين وعهدة؛
  لا يمس حساب المبيعات `4100-SALES` ولذلك لا يحتسب إيراد البيع مرتين.
- تسليم النقد والبضاعة يبدأ `submitted` (والأوف لاين محليًا
  `submitted_pending_sync`) ولا ينقل الأصل حتى مراجعة المشرف. المراجعة تنقل النقد من
  عهدة المندوب إلى الصندوق والبضاعة من السيارة إلى مخزن الاستلام وتسجل الفارق.
- واجهة هاتف متجاوبة في `representative.html` بنفس الزجاج الداكن والألوان الحالية:
  المسار والعملاء، البيع بالباركود، الطلب، المرتجع، التحصيل، العهدة، والمعلق والتعارضات.
- IndexedDB ينزل نطاق المندوب والمواد والأسعار والعملاء والديون ومخزون السيارة، ويفحص
  حدود المخزون والائتمان والعهدة محليًا، ويمنع عملية جديدة أثناء انتظار مراجعة تسليم،
  ويعيد الحالة المحلية عند رفض الخادم. المزامنة تعمل عند الفتح والاستئناف وعودة الاتصال.
- عمليات `representative.*` تستخدم UUID وتسلسل الجهاز وبصمة المحتوى؛ إعادة الإرسال تعيد
  النتيجة نفسها، والرفض يسجل `sync_conflicts` ويظهر في الواجهة ولا يحذف العملية المحلية.

## لم يُنفذ بعد

- الموظفون والحضور والإجازات ودورات الرواتب والصرف والترحيل المحاسبي.
- تطبيق Android/Room الأصلي، تتبع GPS وخريطة المسار، إشعارات المشرف، وطباعة مندوب
  حرارية فعلية. واجهة المندوب الحالية Web/IndexedDB مناسبة للهاتف وليست تطبيق Android.
- شاشة إدارة مرئية للمشرف لإنشاء المستخدم/المندوب وتوزيع العملاء والمسارات والتحميل
  ومراجعة التسليمات؛ العقود والصلاحيات والمعاملات لهذه الأعمال منفذة ومختبرة عبر API،
  بينما الواجهة المنفذة الآن هي واجهة المندوب الهاتفية.
- حجز مركزي للبضاعة المقدمة ضمن تسليم `submitted`: العميل المحلي يمنع عمليات جديدة حتى
  المراجعة، والخادم يعيد تعارضًا ذريًا إذا تغير مخزون السيارة قبل المراجعة، لكن لا يوجد
  مخزن escrow منفصل للبضاعة المسلمة بعد.
- دورة طلب/أمر شراء قبل الاستلام، التسعير والضرائب والخصومات متعددة القوائم، وحدود
  الموافقات والائتمان الخاصة بكل شركة. المرحلة الحالية تعتمد مستندات نهائية مباشرة.
- شاشة إدارة مركزية لتوزيع المخصصات بين عدة أجهزة بدل زر إعداد الجهاز الأولي، وربط
  طابعات حرارية فعلية وتجارب الأجهزة. الطباعة الحالية تستخدم متصفح الويب.
- المطعم: تذاكر المطبخ والوصفات وتقسيم الحساب. المؤسسات: عروض الأسعار والمشاريع
  والموافقات. الواجهات الحالية تنفذ البيع والشفت والسياق التشغيلي المشترك فقط.
- ترحيل بيانات MongoDB القديمة، اختبارات الأجهزة، النسخ الاحتياطي، وتجهيز الإنتاج.

## نتيجة التحقق المحلي

بتاريخ 2026-10-02: نجحت حزمة الاختبارات المحلية: 21 اختبارًا منفذًا وناجحًا، مع اختبار
PostgreSQL الاختياري متجاوزًا عند غياب `TEST_DATABASE_URL`. ثم شُغل اختبار التكامل
نفسه منفردًا على PostgreSQL 17 الحقيقي ونجح. شملت الاختبارات تحويل
الوحدات، الكسور الدقيقة، الشراء والبيع والمرتجعات والدفعات، عزل الشركات، إعادة الإرسال،
نفاد المخزون، وفشلًا متعمدًا بعد بدء الكتابة أثبت rollback الوثيقة والمخزون والقيد وoutbox.
كما تحققت triggers منع حذف المستندات المالية والتجارية. لم يحدث نشر،
ولم تُنشأ خدمة مدفوعة أو مورد خارجي.

اختبارات الكاشير شملت ثلاثة أجهزة وثلاث واجهات، فتح الشفت، النقدي والآجل والمختلط،
الخصم المسموح والمرفوض، مخصص الجهاز، البيع عبر `/sync/push`، إعادة الإرسال، المرتجع،
الوصل، وإغلاق الشفت وتسوية النقد، ومنع البيع المركزي من استهلاك مخزون محجوز لجهاز
أوف لاين. نُفذت دورة PostgreSQL فعلية للعهدة والبيع والإغلاق.

اختبارات المندوبين شملت إنشاء المندوب وصلاحياته وإسناد العميل والمسار، عزل شركتين،
تحميل السيارة، بيعًا نقديًا/آجلًا مختلطًا، مرتجعًا نسبيًا، فشل حد الائتمان بلا أي كتابة،
إعادة إرسال العملية المرفوضة والناجحة، ظهور التعارض، التحصيل، وعدم إنشاء سطر إيراد جديد
للتحصيل، وتسليم النقد والبضاعة ومراجعة المشرف وتسوية العهدة إلى صفر. نُفذت دورة مماثلة
فوق PostgreSQL الفعلي وتحققت قيود RLS والمعاملة.

لم يُختبر على جهاز هاتف فعلي: تغيّر الشبكة الخلوية الحقيقي، استعادة IndexedDB بعد قتل
المتصفح، المسح بكاميرا/قارئ باركود، GPS، الطابعة الحرارية، وأداء الشاشة مع بيانات كبيرة.
اختبار الانقطاع الحالي محاكاة موثقة لطابور محلي ثم إعادة إرسال وتكرار ورفض. لم يحدث نشر،
ولم تُنشأ خدمة مدفوعة أو مورد خارجي.
